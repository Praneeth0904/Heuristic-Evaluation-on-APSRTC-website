# 🌟 Project Overview

The APSRTC website serves thousands of passengers daily for bus ticket booking, route information, schedules, and travel-related services.

This case study focuses on evaluating the website's usability through a structured heuristic review to uncover:

* User experience pain points
* Interface inconsistencies
* Navigation challenges
* Accessibility concerns
* Booking flow friction
* Information architecture issues

The objective was to improve the overall user experience by identifying usability violations and providing practical design recommendations.

# 🎯 Problem Statement

The APSRTC website contains multiple functionalities including:

* Ticket Booking
* Route Search
* Reservation Management
* Bus Pass Services
* Online Payments
* Customer Support

Due to the complexity of these services, users often encounter usability issues that affect efficiency, satisfaction, and task completion.

The challenge was to systematically evaluate the interface and identify areas requiring improvement.

# 🔍 Evaluation Process

## Step 1 — Website Exploration

Conducted a detailed walkthrough of:

* Homepage
* Booking Flow
* Search Experience
* Reservation Pages
* User Management Features
* Payment Process

---

## Step 2 — Heuristic Mapping

Each interface element was evaluated against Nielsen's usability principles.

```text
Screen → Observation → Heuristic Violation → Severity → Recommendation
```

---

## Step 3 — Issue Documentation

Every usability issue was documented with:

* Screenshot
* Description
* Impact
* Severity Score
* Recommendation

---

## Step 4 — Severity Assessment

Issues were prioritized based on impact and frequency.

---

# 🚨 Key Findings

## 1. Visibility of System Status

### Observation

Users are not always informed about system activity, loading states, or progress during critical tasks.

### Impact

* Creates uncertainty
* Increases anxiety
* Leads to repeated actions

### Recommendation

* Add loaders
* Progress indicators
* Status feedback messages

### Severity

🔴 Major

---

## 2. Match Between System and Real World

### Observation

Some labels and terminology are difficult for average users to understand.

### Impact

* Increased cognitive load
* Reduced task efficiency

### Recommendation

* Use familiar language
* Simplify transportation-related terminology

### Severity

🟠 Moderate

---

## 3. User Control and Freedom

### Observation

Users have limited recovery options after making mistakes.

### Impact

* Frustration
* Increased abandonment rate

### Recommendation

* Add undo options
* Improve navigation flexibility

### Severity

🔴 Major

---

## 4. Consistency and Standards

### Observation

Visual elements, labels, and interactions are not consistently applied.

### Impact

* Confusing experience
* Reduced learnability

### Recommendation

* Establish a unified design system
* Standardize components

### Severity

🟠 Moderate

---

## 5. Error Prevention

### Observation

Forms allow errors before validation occurs.

### Impact

* Failed submissions
* Increased correction effort

### Recommendation

* Inline validation
* Preventive input constraints

### Severity

🔴 Major

---

## 6. Recognition Rather Than Recall

### Observation

Users must remember information between steps.

### Impact

* High mental effort
* Reduced usability

### Recommendation

* Surface important information
* Use contextual guidance

### Severity

🟠 Moderate

---

## 7. Flexibility and Efficiency of Use

### Observation

Frequent users lack shortcuts and optimization features.

### Impact

* Slower task completion

### Recommendation

* Quick actions
* Saved preferences
* Recent searches

### Severity

🟡 Minor

---

## 8. Aesthetic and Minimalist Design

### Observation

Information density creates visual clutter.

### Impact

* Reduced readability
* Poor visual hierarchy

### Recommendation

* Simplify layouts
* Improve spacing
* Prioritize content

### Severity

🔴 Major

---

## 9. Error Recovery

### Observation

Error messages do not always provide actionable guidance.

### Impact

* User confusion
* Increased failure rates

### Recommendation

* Clear and specific error messaging

### Severity

🟠 Moderate

---

## 10. Help and Documentation

### Observation

Guidance and support content are difficult to locate.

### Impact

* Increased support dependency

### Recommendation

* Improve accessibility of help resources

### Severity

🟡 Minor
